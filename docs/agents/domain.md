# Domain Docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root contains domain terminology.
- `docs/adr/` contains architecture decision records.

Before exploring an area, read the glossary and ADRs relevant to that area.
If they do not exist, proceed silently; do not suggest creating them upfront.
The domain-modeling skill creates them when terms or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses, and tests.
If a needed concept is absent, consider whether it is unfamiliar language or
a genuine gap to discuss through domain modeling.

If a proposal contradicts an existing ADR, explicitly identify the conflict
rather than silently overriding the decision.
